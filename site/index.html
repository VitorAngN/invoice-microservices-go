Faturamento em Microsserviços

Dois serviços em Go que se comunicam por HTTP para emitir notas fiscais e dar baixa no estoque, com foco no que costuma quebrar em sistemas distribuídos: cliques simultâneos, repetição de requisições e serviço fora do ar.

1única baixa de estoque, mesmo com 6 cliques ao mesmo tempo

Destaques de engenharia

Impressão à prova de clique duplo

Um UPDATE condicional troca a nota de Aberta para Processando: só uma requisição vence, as outras recebem 409 e o estoque é debitado uma única vez.

Baixa atômica

Todos os itens da nota são debitados numa transação com WHERE balance >= q. Se um item não tem saldo, nenhum é debitado, e o saldo nunca fica negativo.

Idempotência

Cada baixa leva Idempotency-Key: invoice-<id>, gravada na mesma transação. Se a resposta se perder e o faturamento repetir, o estoque não debita de novo.

Resiliência

Cliente HTTP com timeout e backoff exponencial que só repete falhas de rede e 5xx. Com o estoque fora do ar, a API responde 503 e a nota volta para Aberta.

Testes de verdade

Testes de unidade e concorrência com go test -race, e um teste ponta a ponta que sobe os dois serviços com PostgreSQL no GitHub Actions a cada push.

Entrega

Binários estáticos em imagens distroless sem root, Docker Compose subindo banco e serviços, encerramento gracioso e /health em cada serviço.
